# VaultGuard Security Threat Model (22 Attack Vectors)

VaultGuard is engineered around a strict separation of duties:
- **Intelligence Layer:** NEAR AI Cloud / Private Verifier (zero signing authority).
- **Cryptographic Trust Layer:** Domain-separated canonical Ed25519 attestations (`VAULTGUARD_ATTESTATION_V1`) + independent GitHub PR verification.
- **Enforcement Layer:** NEAR Rust Policy Smart Contract (`policy-guard.vaultguard.testnet`) + Bounded Treasury Custody (`treasury-custody.vaultguard.testnet`).
- **Settlement Layer:** NEAR Intents 1Click cross-chain settlement with mandatory destination proof verification.

---

## 22 Analyzed Threat Vectors

| # | Threat Vector | Attacker Objective | Attack Surface | Defense Mechanism | Executed Test Case | Expected Result |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **Prompt Injection** | Trick LLM into overriding limits or sending funds to attacker wallet | Invoice description, PDF text, PR body | Untrusted text sanitization, regex injection scanner, and independent onchain integer policy enforcement even if LLM recommends `APPROVE` | `npm run test:prompt-injection` & `tests/integration/lifecycle.test.ts` | `ERR_POLICY_SPEND_LIMIT_EXCEEDED` · 0 funds transferred |
| **2** | **Malicious PDFs** | Execute embedded scripts/macros or exploit parser | Uploaded invoice file (`rawDocumentText`) | Strict MIME check, 5 MB cap, active content signature scanner (`/JavaScript`, `/Launch`, `<script>`) | `packages/evidence/document-integrity.ts` | `ERR_UNSAFE_DOCUMENT` |
| **3** | **Fake Vendor Identities** | Submit invoice under an unregistered or suspended vendor ID | `POST /api/invoices`, `authorize_invoice` | Onchain `LookupMap<String, VendorEntry>` requiring `status == ACTIVE` | `npm run test:vendor-whitelist` | `ERR_UNWHITELISTED_VENDOR` |
| **4** | **Recipient Substitution** | Redirect approved vendor payment to an attacker wallet | Invoice `destinationWallet` or post-authorization transfer call | Vendor registry binds each vendor ID to an exact whitelisted wallet; custody adapter verifies exact match | `G1-03` (`treasury-custody.test.ts`) | `ERR_UNWHITELISTED_RECIPIENT` / `ERR_QUOTE_MISMATCH` |
| **5** | **Amount Manipulation** | Inflate payment above $500 single cap or alter amount after signing | `authorize_invoice`, `executeBoundedTreasuryTransfer` | Pure `BigInt` / `U128` base-unit validation (`<= 500_000_000`) and canonical Ed25519 signature over `amount_base_units` | `G1-04`, `G2-08`, `npm run test:spend-limit` | `ERR_POLICY_SPEND_LIMIT_EXCEEDED` / `ERR_INVALID_ATTESTATION` |
| **6** | **Duplicate Invoices** | Get paid twice for the same invoice ID or identical document content | `POST /api/invoices`, `authorize_invoice` | Onchain `processed_invoice_ids` and `processed_invoice_hashes` (`SHA-256`) sets | `npm run test:duplicate-invoice` | `ERR_DUPLICATE_INVOICE` |
| **7** | **Replay Attacks** | Replay a valid signed attestation or execution nonce | `authorize_invoice`, `executeSettlement` | Unique `attestation.nonce`, `executionNonce`, and `idempotencyKey` tracked in consumed sets | `G1-05`, `G2-05`, `G3-07` | `ERR_NONCE_ALREADY_USED` |
| **8** | **Forged Attestations** | Fabricate an attestation or sign with an untrusted Ed25519 keypair | `authorize_invoice` | `near_sdk::env::ed25519_verify` / `crypto.verify` against onchain `trusted_verifiers` list | `G2-01`, `G2-02`, `G2-09` | `ERR_INVALID_SIGNATURE` / `ERR_INVALID_ATTESTATION` |
| **9** | **Expired Attestations** | Submit a delayed or captured attestation after its validity window | `authorize_invoice` | Mandatory check `now_ms <= attestation.expires_at` | `G2-04` (`tee-attestation.test.ts`) | `ERR_ATTESTATION_EXPIRED` |
| **10** | **Unauthorized Function Call Key Use** | Use agent key to transfer native NEAR, call external contracts, or change policy | NEAR Access Key boundary (`access-keys.ts`) | Function Call Key restricted to `policy-guard.vaultguard.testnet`, 4 methods, 0 native NEAR deposit allowance | `G1-01`, `G1-02`, `G1-11` | `ERR_UNAUTHORIZED_AGENT` / `ERR_UNAUTHORIZED_ADMIN` |
| **11** | **Compromised Administrator** | Unauthorized policy change or silent mainnet drain | Admin endpoints & mainnet execution | Separation of policy contract from custody account; explicit per-transaction human confirmation for mainnet | `G3-14` (`intents-settlement.test.ts`) | `ERR_UNAUTHORIZED_ADMIN` |
| **12** | **Concurrent Spending** | Submit parallel invoices to race past the $2,000 daily limit | `authorize_and_reserve_spending` | Atomic reservation locks `active_reserved_base_units` prior to async settlement | `npm run test:concurrency` | `ERR_INSUFFICIENT_AVAILABLE_LIMIT` |
| **13** | **Daily-Limit Bypass** | Exceed $2,000.00 USDC cumulative 24h spend across multiple small invoices | `authorize_invoice` | Cumulative check: `daily_used + active_reserved + amount <= 2_000_000_000` | `npm run test:daily-limit` | `ERR_DAILY_LIMIT_EXCEEDED` |
| **14** | **Settlement Quote Manipulation** | Tamper with quote recipient, amount, token, chain, or slippage (>50 bps) | `POST /api/settlements/execute` | `verifyQuoteAgainstAuthorization` cross-checks every quote field against the bounded reservation | `G3-01`..`G3-04`, `G3-15`, `G3-16` | `ERR_QUOTE_MISMATCH` |
| **15** | **Deposit Address Substitution** | Swap 1Click deposit address with an attacker NEAR account | `quote.depositAddress` | Deterministic deposit address binding (`computeCanonicalDepositAddress`) | `G3-05` (`intents-settlement.test.ts`) | `ERR_QUOTE_MISMATCH` |
| **16** | **Forged Settlement Callbacks** | Send fake webhook claiming settlement succeeded without onchain tx | Settlement confirmation | `verifyDestinationSettlementProof` rejects webhook-only callbacks and requires verified destination tx hash | `G3-08`, `G3-09`, `G3-10` | `ERR_SETTLEMENT_NOT_CONFIRMED` |
| **17** | **Database Race Conditions** | Double-submit same invoice or idempotency key concurrently | Backend API & DB layer | Unique constraints on `invoice_number`, `invoice_hash`, `attestation_nonce`, and `idempotency_key` | `G3-07`, `G3-13` | `ERR_DUPLICATE_INVOICE` / `ERR_NONCE_ALREADY_USED` |
| **18** | **API Authorization Bypass** | Invoke admin endpoints using AI agent or operator role | `PATCH /api/policies`, `POST /api/vendors` | Server-side `assertAdmin` check on caller account | `G1-11` | `ERR_UNAUTHORIZED_ADMIN` |
| **19** | **SSRF (Server-Side Request Forgery)** | Pass internal/localhost URL as `proofOfWorkRef` to probe internal network | `verifyGitHubProofOfWork` | Strict regex allowlist `^https://github\.com/([A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+)/pull/(\d+)$` | `packages/evidence/github-verifier.ts` | `ERR_INVALID_PROOF_OF_WORK` |
| **20** | **CSRF** | Cross-site state mutation | `/api/*` | JSON-only API with custom `x-near-account-id` header requirement | `server.ts` | Rejected |
| **21** | **Secret Leakage** | Expose private keys or confidential invoice text onchain or in frontend | API responses, NEAR contract state | Confidential documents encrypted at rest (`AES-256-GCM`); only SHA-256 hash stored onchain | `tests/unit/core.test.ts` | Verified |
| **22** | **Denial of Service through Uploads** | Exhaust memory with oversized invoice payloads | `express.json({ limit: '5mb' })` + `validateDocumentSafety` | Hard 5 MB byte check before parsing | `packages/evidence/document-integrity.ts` | `ERR_FILE_TOO_LARGE` |
